# Project constitution — stable truths, creative discretion, escalation

## Hierarchy

1. Explicit, most-recent user direction (including approval/rejection).
2. Constitution, locked story, locked project constraints.
3. Current reviewed status/approved assets/shot cards.
4. Domain rulebooks and agreed production standards.
5. Tool defaults and creative suggestions.
6. V2 historical archive (for understanding past decisions, not automatic override).

## Locks that cannot silently change

| Lock | Reason | Escalate when |
|---|---|---|
| Actual emergence THROUGH portal | Historical critical failure | Portal geometry is inadequate; propose rig/camera change, never screen-edge entrance |
| Human rescues egg; mother interprets threat | Core misunderstanding | Story logic weakened or rescue made offscreen |
| Baby hatches, reunited, follows human | Emotional reversal and twist | Motivations disappear or chronology breaks |
| Paper-cut 2.5D character rigs | Coherent artistic and motion identity | Flat layer translation replaces acting |
| Camera/motion/audio chosen from dramatic context | User's explicit research priority | Any department moves only to appear busy |
| 9s first, then 80s | Approved stage order | Agent tries to rush to the final film |
| Silent story comprehension | Film's no-narrator design | User requests narration or significant dialogue |
| Actual evidence before “pass” | Hallucination countermeasure | Files, logs, renders or observations missing |

## Creative freedoms

Exact character design, accents and color palette; number of secondary cutaways; head/pupil expressions; small pacing shifts; paper texture treatment; original Foley design; instrumentation of original score; comedic pauses. Changes must preserve physical action, geography and emotional logic. More time is not automatically better; improve readability first.

## Decision procedure for any creative proposal

Describe: **Existing problem → character/audience need → new decision → effects on motion/camera/sound → tradeoff → observable success test → documents requiring update.** Prefer the smallest change that solves the problem. Avoid piling on transitions, shake, motion blur or captions to mask weak blocking.

## Project settings

- Format: 1080×1920, 30fps, approx 80s total, editorial may revise only after written timeline update.
- 8 narrative scenes at `0–9, 9–19, 19–30, 30–46, 46–56, 56–66, 66–74, 74–80` seconds.
- Action occurs primarily on a consistent 2.5D east-west world axis; foreground/background layers used with coherent depth.
- Vertical safe-area placeholders: top 170px and bottom 260px, conservative right UI allowance; test against actual platform before delivery.
- No forced voiceover; designed nonverbal performance, restrained captions if absolutely needed.
- Original or properly licensed sounds/music only; verify licensing and reproducibility.
- Audio mixing: tune to target platform and listening conditions; **do not assume -23 LUFS broadcast standard applies to a YouTube upload**.

## Definitions

- **Action completion:** the viewer actually sees the decisive event cross its physical threshold (e.g., crossing, catching, impact, release).
- **Context-driven direction:** camera, motion and audio choices have explicit narrative function and viewer perspective.
- **Benchmark approval:** all blocker/major defects closed with actual verification and no uncontrolled scene-to-scene side effects.
